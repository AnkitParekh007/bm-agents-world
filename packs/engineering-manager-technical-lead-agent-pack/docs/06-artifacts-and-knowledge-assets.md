# Artifacts and Knowledge Assets

## Artifact registry

| Artifact | Purpose |
| --- | --- |
| `engineering-daily-summary` | Daily priorities, risks, decisions, blockers, and follow-ups. |
| `engineering-delivery-plan` | Workstreams, slices, milestones, ownership, dependencies, forecasts, and evidence. |
| `capacity-scenario` | Availability, operational load, planned allocation, assumptions, and alternatives. |
| `sprint-health-report` | Goal alignment, progress, WIP, aging, blockers, scope changes, and carryover risk. |
| `dependency-map` | Cross-team, system, vendor, environment, and decision dependencies. |
| `engineering-risk-register` | Delivery, technical, quality, security, reliability, people-process, and vendor risks. |
| `technical-decision-record` | Context, options, tradeoffs, recommendation, decision owner, and follow-up. |
| `architecture-alignment-report` | Conformance, deviations, exceptions, and required architecture actions. |
| `pull-request-review-summary` | Scope, evidence, reviewer coverage, unresolved findings, and readiness. |
| `quality-engineering-report` | Test coverage, defects, regression, environments, and quality risks. |
| `security-risk-summary` | Security, privacy, compliance, findings, exceptions, and remediation. |
| `operational-readiness-review` | SLOs, observability, runbooks, capacity, resilience, and support readiness. |
| `release-readiness-report` | Cross-discipline evidence and go, conditional-go, or no-go recommendation. |
| `incident-brief` | Impact, timeline, current state, decisions, actions, and communications. |
| `post-incident-review` | Blameless analysis, contributing conditions, lessons, and corrective actions. |
| `technical-debt-register` | Debt items, impact, evidence, owner, priority, and modernization path. |
| `developer-experience-assessment` | Journey friction, feedback loops, cognitive load, and improvement options. |
| `engineering-metrics-dashboard-spec` | Metric definitions, owners, sources, interpretation, and guardrails. |
| `team-health-summary` | Aggregate, privacy-preserving team health and collaboration findings. |
| `one-on-one-agenda` | Employee-selected topics, prior actions, recognition, coaching questions, and follow-up. |
| `growth-development-plan` | Human-reviewed goals, evidence, learning, mentoring, and opportunities. |
| `hiring-interview-plan` | Role capabilities, structured interviews, panel coverage, and scorecards. |
| `onboarding-plan` | Access, project context, architecture, codebase, tooling, practices, and checkpoints. |
| `stakeholder-engineering-update` | Progress, outcomes, risks, decisions, forecast, and asks. |
| `improvement-experiment` | Hypothesis, intervention, metrics, guardrails, duration, and review. |
| `approval-request` | Payload-bound request with action, hash, scope, approvers, expiry, and status. |
| `audit-evidence-bundle` | Immutable provenance, inputs, decisions, approvals, outputs, and execution references. |

## Knowledge sources

Authoritative sources include Jira/Confluence, repository and CI evidence, architecture decisions, service catalogs, approved engineering metrics, observability, incident records, runbooks, career frameworks, and organization policies. Chat messages and model-generated text are not authoritative unless published to an approved system by an accountable owner.

## Retention and privacy

One-on-one, growth, team-health, and candidate artifacts use restricted storage, short retention, purpose limitation, and human-controlled access. Raw employee surveillance data and private communications are not valid inputs.
