# Observability, Audit, and Evaluation

## Runtime observability

Capture run ID, customer/account scope, source systems, tool calls, policy decisions, approval checkpoints, generated artifacts, publication results, and cross-pack handoffs. Log metadata and hashes rather than raw customer content whenever possible.

## Agent quality metrics

Evaluate factual accuracy, evidence traceability, data freshness, account/tenant isolation, health-score calibration, risk-alert precision/recall, value-claim support, communication approval compliance, and cross-functional routing accuracy.

## Customer Success outcome metrics

Useful program metrics can include onboarding completion, time-to-first-value, time-to-value, success-plan progress, product adoption, customer satisfaction, risk recovery, support burden, renewal readiness, customer-confirmed value, advocacy participation, and intervention effectiveness. Metric ownership and definitions must be approved.

## Health-score evaluation

Track false positives, false negatives, stale signals, segment bias, manual overrides, and downstream actions. A composite score is never sufficient evidence by itself; reviewers should inspect the underlying drivers.

## Communication evaluation

Measure factual correction rate, approval rejection reasons, commitment-language violations, customer-response outcomes, and unnecessary-contact rate. Do not optimize for message volume.

## Audit

Sensitive reads and writes record who requested the run, why access was needed, which customer was in scope, which fields were retrieved, which approval authorized publication, and what exact payload was sent.
