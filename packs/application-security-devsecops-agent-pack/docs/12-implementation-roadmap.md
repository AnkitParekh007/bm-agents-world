# Implementation Roadmap

## Phase 0 — Governance

Approve the security charter, risk tiers, data boundaries, test authorization, remediation SLAs, exception policy, production boundaries, and accountable owners.

## Phase 1 — Read-only context and evidence

Connect Jira, Confluence, Bitbucket, source intelligence, vulnerability intelligence, package metadata, and the security artifact store.

## Phase 2 — Isolated deterministic scanning

Enable repository profiling, SAST, SCA, secrets, API linting, SBOM, signature verification, container, IaC, and Kubernetes scanning.

## Phase 3 — Threat modeling and secure design

Pilot security requirements, threat models, architecture reviews, and risk-based security test plans on selected changes.

## Phase 4 — Vulnerability operations

Enable structured triage, remediation plans, SLAs, verification, exception requests, and governed Jira updates.

## Phase 5 — Release and supply-chain assurance

Bind scans to candidates, generate SBOM and provenance, verify signatures, and produce human-owned security gate decisions.

## Phase 6 — Controlled dynamic testing

Add approved non-production DAST, API security tests, fuzzing, and independent penetration-test coordination.

## Phase 7 — Product-security incidents and program improvement

Integrate sensitive incident workflows, disclosure inputs, recurring weakness analysis, metrics, and SAMM/SSDF improvement planning.
