# Research and Standards Notes

## Style and editorial guidance

Project-specific style guides remain authoritative. Google and Microsoft guidance provide useful defaults for clear, concise, direct, scannable, developer-oriented technical content. The pack uses configurable style rules rather than hard-coding one corporate voice.

## Content architecture

Diátaxis is used to distinguish tutorials, how-to guides, explanations, and reference material. DITA is supported as an optional structured-authoring format for organizations that already use topic-based reuse and publishing.

## Accessibility

Rendered documentation, diagrams, media, navigation, tables, and interactions should meet the project accessibility policy, with WCAG 2.2 as the baseline in this pack.

## API documentation

OpenAPI and AsyncAPI are treated as machine-readable sources for reference and examples. Repository-approved specification versions control. The agent validates rather than silently upgrades contracts.

## Docs as code

The pack treats documentation changes like software changes: version control, focused diffs, automated validation, review, preview, traceability, and rollback. This does not require every audience or content collection to use the same source format.

## AI controls

Generated documentation is not authoritative until evidence, deterministic checks, independent review, and required approval are complete. Unsupported claims, fabricated citations, invented behavior, untested procedures, and leaked sensitive information are release blockers.
