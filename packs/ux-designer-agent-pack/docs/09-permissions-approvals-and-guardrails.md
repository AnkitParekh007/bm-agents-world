# Permissions, Approvals, and Guardrails

## Safe autonomous actions

- Read authorized Jira, Confluence, Figma, Storybook, Bitbucket, design-system, analytics, and redacted research context.
- Analyze requirements, flows, accessibility, content, consistency, and implementation evidence.
- Create isolated drafts, research plans, design briefs, wireframes, prototype specifications, handoff drafts, and QA reports.
- Run deterministic contrast, target-size, token, content, accessibility, and visual-diff checks.

## Human approval required

- Participant recruitment, contact, consent workflow, incentives, or recording.
- Survey distribution, unmoderated test launch, or experiment launch.
- Shared Figma file edits, branch merge, component/variable publication, or library release.
- Jira, Confluence, Teams, or stakeholder publication.
- Production screenshots or observation involving real user data.
- Acceptance of critical accessibility, privacy, or usability risk.

## Prohibited autonomous actions

- Expose raw credentials or direct participant identifiers.
- Invent user research, quotes, analytics, or test results.
- Modify production applications, data, feature flags, experiments, or analytics definitions.
- Publish or merge shared design libraries without owner approval.
- Contact users from unapproved lists or infer sensitive traits.
- Use unlicensed fonts, images, icons, or proprietary assets.
- Defeat consent, retention, privacy, accessibility, or security controls.

## Approval binding

Approvals bind run ID, requester, project, action, exact target, payload or design hash, participant/study ID where applicable, environment, expiry, and approver. Material changes invalidate approval.
