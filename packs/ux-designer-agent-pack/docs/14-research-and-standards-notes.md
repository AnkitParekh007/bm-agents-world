# Research and Standards Notes

## Accessibility baseline

- WCAG 2.2 is the normative web accessibility baseline used by this pack.
- WAI-ARIA Authoring Practices Guide supplies practical widget and keyboard patterns but is not itself a complete design system or replacement for native HTML semantics.
- Accessibility evaluation combines design review, deterministic checks, code/component evidence, browser behavior, and human testing where appropriate.

## Figma integration

Figma's official MCP server can expose structured design context including components, variables, Dev Mode information, and Code Connect relationships. Write-to-canvas capabilities are treated as privileged and approval-controlled. Seat and plan requirements must be verified during onboarding.

## Component documentation

Storybook is used as a read-oriented catalog for implemented components, states, documentation, accessibility results, and visual baselines. It complements Figma; neither source alone proves implementation quality.

## Research ethics and privacy

- Obtain informed consent for participation and recording.
- Collect only data needed for the research decision.
- Keep contact data, consent records, incentives, recordings, and raw transcripts in approved repositories.
- Redact direct identifiers before agent analysis.
- Never invent participants, quotes, observations, or quantitative results.

## Design tokens and interoperability

The pack models tokens semantically and validates mappings to code. Tooling and standards in this area evolve, so every project must resolve its actual token format, transformer, component implementation, and ownership rather than assuming one universal schema.
